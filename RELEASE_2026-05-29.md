## Scope for this release
- Web messenger stability on production domain
- Auth/session hardening and logout reliability
- Dialogs/messages reliability (send/retry/realtime sync)
- Chat persistence after relogin and after 24h session gap
- Media upload/download baseline quality
- Core Android parity for auth/dialogs/chat

## Mandatory quality gates
1. Monorepo checks pass:
   - `npm run check`
2. Docker build check passes:
   - `npm run check:docker`
3. Frontend smoke passes in release env:
   - `npm --workspace apps/frontend run test:smoke`
4. Security local audit reviewed:
   - `security-audit/local/report.md` updated

## Deployment checklist
1. Verify `.env` secrets (JWT, DB, CORS allowlist)
2. Backup DB before deploy (`scripts/backup-postgres.sh`)
3. Run migrations on target
4. Deploy backend, frontend, mtproto
5. Validate endpoints:
   - `/health`
   - `/api/*`
   - `/ws` websocket upgrade
6. Validate login/register/logout on production domain
7. Validate message send/edit/delete + media flow
8. Validate chat history persistence after logout/login
9. Re-check same account after 24h: dialogs/messages must still be present and synced

## Production routing rule
- Public messenger domain: `https://web.thegrapht.su`
- Public site domain: `https://thegrapht.su`
- Container binds `127.0.0.1:*` are internal-only upstreams for nginx and are not user-facing URLs.
- Release verification must be executed on `web.thegrapht.su` for UI/API/WS flows.

## Dev isolation before release
- Isolated pre-prod messenger domain: `https://dev.thegrapht.su`
- Dev stack file: `docker-compose.dev.yml`
- Dev routing and promote flow document: `DEV_RELEASE_FLOW_2026-05-29.md`
