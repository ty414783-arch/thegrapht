# Регламент разработки и автоматического деплоя в продакшн (TheGraphT)

Дата последнего обновления: **30 мая 2026 г.**

---

## 1. Архитектура сред и изоляция

Для обеспечения стабильности основного мессенджера (`https://web.thegrapht.su`) развернуты две полностью изолированные среды:

| Среда | Домен | Путь к коду на сервере | База данных PostgreSQL | Файлы загрузок |
| :--- | :--- | :--- | :--- | :--- |
| **Production** | `https://web.thegrapht.su` | `/root/thegrapht` | `thegrapht` (основной том) | `/root/thegrapht-data/uploads` |
| **Development** | `https://dev.thegrapht.su` | `/root/thegrapht-dev` | `thegrapht_dev` (dev том) | `/root/thegrapht-data/uploads-dev` |

---

## 2. Процесс разработки и тестирования

Вся разработка, эксперименты и первоначальное тестирование обновлений проводятся **исключительно** в изолированной папке разработчиков.

### Шаги разработки:
1. Перейдите в каталог разработчиков:
   ```bash
   cd /root/thegrapht-dev
   ```
2. Вносите изменения в исходный код фронтенда (`apps/frontend/src/`) или бэкенда (`apps/backend/src/`).
3. При необходимости применить изменения во фронтенде (так как он примонтирован напрямую):
   - Если это CSS/HTML/JS логика фронтенда, она подхватывается dev-контейнером автоматически.
   - Для надежности или при изменении конфигураций перезапустите dev-контейнеры:
     ```bash
     docker compose -f docker-compose.yml -f docker-compose.dev.yml -p thegrapht restart frontend-dev
     ```
4. Откройте **`https://dev.thegrapht.su`** в браузере и протестируйте изменения (авторизация, отправка сообщений, медиа-файлы и т.д.). Данные будут записываться в изолированную dev-БД, не затрагивая живых пользователей продакшна.

---

## 3. Деплой изменений на продакшн (Промоушен)

Когда изменения на dev-поддомене полностью протестированы и признаны стабильными, их можно перенести на рабочий сервер одной командой с помощью автоматического скрипта промоушена.

### Команда для деплоя:
Запустите скрипт из папки разработки:
```bash
/root/thegrapht-dev/scripts/promote-to-prod.sh
```

### Что скрипт делает под капотом:
1. **Безопасность (Резервное копирование):** Автоматически делает дамп рабочей БД продакшна и сохраняет его в сжатом виде в каталог `/root/thegrapht/backups/`.
2. **Синхронизация кода:** Быстро синхронизирует исходный код фронтенда, бэкенда, mtproto и конфигураций из `/root/thegrapht-dev` в `/root/thegrapht` с помощью `rsync`. При этом **игнорируются** конфигурации `.env`, папки бэкапов, логов и временных файлов (`scratch`).
3. **Обновление контейнеров:** Пересобирает и перезапускает рабочие контейнеры продакшна (`backend`, `mtproto`, `frontend`) без простоя остальных систем (TURN, Postfix).

---

## 4. Экстренный откат (Rollback)

Если после деплоя на продакшн возникла непредвиденная критическая ошибка, вы можете быстро откатиться:

1. **Откат кода:** Синхронизируйте код обратно из последней стабильной резервной копии (или предыдущего коммита).
2. **Откат базы данных (при необходимости):**
   Восстановите резервную копию базы данных, созданную скриптом промоушена перед деплоем. Файлы бэкапов лежат по пути: `/root/thegrapht/backups/thegrapht_*.sql.gz`.
   Используйте стандартный скрипт восстановления или команду:
   ```bash
   gunzip -c /root/thegrapht/backups/thegrapht_TIMESTAMP.sql.gz | docker exec -i thegrapht-postgres-1 psql -U thegrapht_app -d thegrapht
   ```
